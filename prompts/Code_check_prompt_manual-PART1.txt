- A5a. **ROBUST COMMAND SELECTION**: Choose commands that handle various text types robustly (alphanumeric, special characters, Unicode, whitespace):
  - **FILENAME/PATH ROBUSTNESS** (CRITICAL):

    - Only apply `set -E -o errtrace` and ERR trap with `BASH_COMMAND` when `SUPPORTS_ERRTRACE==1` and `IS_BASH==1`.
    - Avoid relying on subshell inheritance of strict mode; for subshells, explicitly restate needed options or use command groups.
  - VALIDATION:
    - Verify that any use of Bash-specific syntax is either:
      1) guarded by `IS_BASH` and/or version checks, or
      2) justified with no viable POSIX alternative (documented inline).
    - Verify that traps using `BASH_COMMAND`/`BASH_SOURCE` are only set when `IS_BASH==1`; otherwise use a simpler message.
    - Verify that functions/blocks that require strict mode explicitly invoke the provided helper(s) instead of assuming inherited state.
  - DETECTION:
    - `grep -nE '\[\[|<\(|readarray|mapfile|declare -A|\(\(' script.sh` to find Bash-only features.
    - `grep -nE 'trap .*ERR' script.sh` to ensure trap uses are gated by `IS_BASH` or use portable fallbacks.
    - Inspect subshells `(` `)` vs groups `{ ...; }` in strict blocks and confirm correct option scoping.
  - AUTO-FIX STRATEGY:
    - Surround Bash-only blocks with:
      ```bash
      if [ "${IS_BASH:-0}" -eq 1 ]; then
        # bash-specific
      else
        # POSIX fallback
      fi
      ```
    - Replace `[[ ... ]]` with `[ ... ]` where feasible; replace process substitution with pipes or temporary files when portability is required.
    - Replace subshells in strict sections with command groups to retain options or re-enable strict options inside the subshell.

C. Variables & Defaults
- C1. Detection/handling of unbound variables with `${var:-default}` or `${var:?message}` as appropriate.
- C2. Correct use of `local`, `readonly`, `declare -r`, exported variables, and avoidance of unintended global state.
  - **CRITICAL**: NEVER use `local` keyword outside a function - this causes error "local: can only be used in a function"
  - Check every `local` declaration is inside a function body
  - For global variables, use plain assignment or `declare` (without `local`)
  - Suggested commands: `grep -n '^[[:space:]]*local ' script.sh` to find `local` declarations, verify each is inside a function
- C3. Safe handling of arrays, indexes, and `IFS` mutations (restore defaults after use).
- C4. Each variable is declared once, with an explicit, meaningful default or guard. Later redeclarations are removed in favor of the carried-forward definition, and usages reference the original declaration.
- C5. **UNBOUND VARIABLE PROTECTION**: When using `set -u` or expecting unbound variables, ensure all variables have defaults:
  - Use `${VAR:-default_value}` pattern consistently
  - For environment variables that may not be set: `CACHE_DIR="${CONTAINER_APT_CACHE:-/var/cache/apt/archives}"`
  - Export critical variables in profile scripts: `/etc/profile.d/*.sh` and `/etc/environment`
  - Add fallback detection logic for missing environment variables before first use
- C6. **VARIABLE DUPLICATION & OVERWRITE PREVENTION**: Maintain dynamic symbol table and prevent unexpected variable reuse:
  - **MANDATORY**: Build and maintain a running symbol table tracking all variable declarations (name, scope: local/global/exported, line number, default value, purpose)
  - **CRITICAL**: Detect duplicate variable declarations - same variable name declared multiple times in same scope
  - **CRITICAL**: Detect variable overwrites - variable assigned new value without explicit intent (may indicate logic error)
  - **REQUIRED**: For each variable declaration, check symbol table for existing entry:
    - If variable exists in same scope → **ERROR**: Duplicate declaration (remove duplicate, use original)
    - If variable exists in different scope → **WARNING**: Potential shadowing (verify intent, document if intentional)
    - If variable overwrites existing value → **WARNING**: Verify overwrite is intentional (add comment explaining why)
  - **SYMBOL TABLE STRUCTURE**: Track for each variable:
    - Variable name (case-sensitive)
    - Scope (local/global/exported/readonly)
    - First declaration line number
    - Default value (if any)
    - Purpose/description (from comments or context)
    - All usage locations (line numbers)
    - Last assignment line number (to detect overwrites)
  - **DETECTION METHOD**:
    1. Extract all variable declarations: `grep -nE '^[[:space:]]*(local |declare |readonly |export )?[A-Za-z_][A-Za-z0-9_]*=' script.sh`
    2. Extract all variable assignments: `grep -nE '^[[:space:]]*[A-Za-z_][A-Za-z0-9_]*=' script.sh`
    3. Build symbol table: For each declaration, add to table; for each assignment, check if variable exists
    4. Cross-reference: Check for duplicates in same scope, overwrites without explicit intent
  - **RISKY BEHAVIORS TO PREVENT**:
    - **RISK 1**: Variable reused for different purpose → May cause logic errors if old value expected
    - **RISK 2**: Global variable overwritten in function → May affect other code expecting original value
    - **RISK 3**: Loop variable reused outside loop → May contain unexpected value from last iteration
    - **RISK 4**: Temporary variable reused without reset → May contain stale data from previous operation
    - **RISK 5**: Configuration variable overwritten → May break downstream code expecting original config
  - **VALIDATION PATTERNS**:
    - **Pattern 1 - Duplicate Declaration**: `VAR=value1` ... `VAR=value2` (same scope) → Remove duplicate, use first declaration
    - **Pattern 2 - Unintended Overwrite**: `CONFIG_DIR="/opt/config"` ... `CONFIG_DIR="/tmp"` (no comment) → Add comment or use different variable
    - **Pattern 3 - Loop Variable Reuse**: `for item in list; do ...; done` ... `echo "$item"` (outside loop) → Use different variable or reset
    - **Pattern 4 - Temporary Variable Reuse**: `TMP=$(mktemp)` ... `TMP=$(mktemp)` (same scope) → Verify old file cleaned up, or use different variable
    - **Pattern 5 - Global Shadowing**: Global `VAR=value1` ... Function `local VAR=value2` → Document intentional shadowing
  - **CROSS-CHUNK TRACKING**: When code is split into chunks:
    - Maintain symbol table across chunks (carry forward from previous chunks)
    - Track variables defined in earlier chunks but used in later chunks
    - Mark variables as "resolved" once safe usage verified in all chunks
    - When duplicate found across chunks, verify if it's intentional (different purpose) or error (same purpose)
  - **AUTO-FIX STRATEGY**:
    - **Duplicate in same scope**: Remove duplicate declaration, update all references to use original
    - **Unintended overwrite**: Add comment explaining overwrite, or rename variable if different purpose
    - **Loop variable reuse**: Use different variable name outside loop, or explicitly reset before use
    - **Temporary variable reuse**: Use unique variable name for each temporary operation, or verify cleanup
    - **Global shadowing**: Document intentional shadowing with comment, or rename local variable
  - **EXAMPLE - WRONG** (duplicate declaration):
    ```bash
    # Line 100: First declaration
    INSTALL_DIR="/opt/myapp"
    
    # Line 500: Duplicate declaration (ERROR - same scope)
    INSTALL_DIR="/usr/local/myapp"  # Overwrites without clear intent
    
    # Line 800: Uses variable (may use wrong value)
    install_files "${INSTALL_DIR}"  # Which value is used?
    ```
  - **EXAMPLE - CORRECT** (single declaration with explicit overwrite):
    ```bash
    # Line 100: Single declaration with default
    INSTALL_DIR="${INSTALL_DIR:-/opt/myapp}"
    
    # Line 500: Explicit overwrite with comment (if intentional)
    # Override install directory for container builds
    INSTALL_DIR="/usr/local/myapp"
    
    # Line 800: Uses variable (clear which value)
    install_files "${INSTALL_DIR}"  # Uses /usr/local/myapp
    ```
  - **EXAMPLE - WRONG** (temporary variable reuse):
    ```bash
    # First operation
    TMP_FILE=$(mktemp)
    process_data > "${TMP_FILE}"
    result1=$(parse_output "${TMP_FILE}")
    rm -f "${TMP_FILE}"
    
    # Second operation (reuses TMP_FILE - risky if first operation failed)
    TMP_FILE=$(mktemp)  # Overwrites, but what if previous cleanup failed?
    process_other > "${TMP_FILE}"
    result2=$(parse_output "${TMP_FILE}")
    ```
  - **EXAMPLE - CORRECT** (unique temporary variables):
    ```bash
    # First operation
    TMP_FILE1=$(mktemp)
    trap 'rm -f "${TMP_FILE1}"' EXIT
    process_data > "${TMP_FILE1}"
    result1=$(parse_output "${TMP_FILE1}")
    
    # Second operation (uses different variable)
    TMP_FILE2=$(mktemp)
    trap 'rm -f "${TMP_FILE2}"' EXIT
    process_other > "${TMP_FILE2}"
    result2=$(parse_output "${TMP_FILE2}")
    ```
  - **SYMBOL TABLE EXAMPLE**:
    ```

      First declared: line 100
      Default value: /opt/myapp
      Purpose: Installation directory for application
      Usage locations: [100, 500, 800]
      Last assignment: line 500
      Status: WARNING - Overwritten at line 500 (verify intent)

      Scope: local (function: process_data)
      First declared: line 200
      Default value: (mktemp output)
      Purpose: Temporary file for data processing
      Usage locations: [200, 201, 202]
      Last assignment: line 200
      Status: WARNING - Reused at line 400 (verify cleanup)
    ```
  - **VALIDATION COMMANDS**:
    - Find all variable declarations: `grep -nE '^[[:space:]]*(local |declare |readonly |export )?[A-Za-z_][A-Za-z0-9_]*=' script.sh`
    - Find duplicate names: `grep -oE '^[[:space:]]*(local |declare |readonly |export )?[A-Za-z_][A-Za-z0-9_]*=' script.sh | sed 's/.*\(local \|declare \|readonly \|export \)?//; s/=.*//' | sort | uniq -d`
    - Find overwrites: Build symbol table, track assignments, flag variables assigned multiple times
    - Cross-reference with usage: `grep -nE '\$\{[A-Za-z_][A-Za-z0-9_]*\}' script.sh` to find all variable usages

D. Quoting & Expansion Safety
- D1. Proper quoting/escaping for variables, command substitutions, arithmetic, glob patterns, and path generation.
- D2. Verification of `read` usage (`read -r`, IFS settings) and word-splitting safeguards.
- D3. **PIPE PATTERN SAFETY**: Avoid unsafe `echo | grep` patterns; prefer here-strings or direct grep on variables:
  - UNSAFE: `if echo "${VARIABLE}" | grep -q "pattern"; then` (creates unnecessary subshell, potential echo flag interpretation)
  - SAFE: `if grep -q "pattern" <<< "${VARIABLE}"; then` (here-string, no subshell, explicit quoting)
  - SAFE: `if [[ "${VARIABLE}" =~ pattern ]]; then` (Bash regex, no external command)
  - Detection: `grep -n 'echo.*|.*grep' script.sh` to find all occurrences
- D3a. **COMPREHENSIVE UNSAFE PIPE PATTERNS**: Check for ALL unsafe pipe patterns beyond `echo | grep`:
  - **UNSAFE PATTERNS**:
    - `echo "${VAR}" | grep` → Use here-string or Bash regex (see D3)
    - `echo "${VAR}" | sed` → Use here-string: `sed 's/old/new/' <<< "${VAR}"`
    - `echo "${VAR}" | awk` → Use here-string: `awk '{...}' <<< "${VAR}"`
    - `echo "${VAR}" | cut` → Use here-string: `cut -d: -f1 <<< "${VAR}"`
    - `echo "${VAR}" | sort` → Use here-string: `sort <<< "${VAR}"`
    - `echo "${VAR}" | head/tail` → Use here-string: `head -n1 <<< "${VAR}"`
    - `printf "${VAR}" | command` → Use here-string: `command <<< "${VAR}"`
    - `cat file | grep` → Use direct input: `grep pattern file` (no pipe needed)
    - `cat file | while read` → Use direct input: `while IFS= read -r line < file` or `grep pattern file | while read`
  - **SAFE ALTERNATIVES**:
    - For variables: Use here-strings (`<<< "${VAR}"`) or Bash built-ins (`[[ ]]` regex)
    - For files: Use direct input (`command file`) or process substitution (`< file`)
    - For arrays: Use process substitution or here-string: `grep pattern <(printf '%s\n' "${array[@]}")`
  - **DETECTION**: Find all pipe patterns: `grep -nE '[^|]\|[^|]' script.sh`, then analyze each for safe alternatives
  - **VALIDATION**: For each pipe pattern, verify if here-string or direct input would work better
- D3b. **ECHO UNSAFE PATTERNS**: Check for unsafe `echo` usage patterns:
  - **UNSAFE PATTERNS**:
    - `echo -e "${VAR}"` → Variables may contain escape sequences (`-e`, `-n`) that echo interprets as flags
    - `echo -n "${VAR}"` → Variables starting with `-n` or containing `\c` can cause unexpected behavior
    - `echo "${VAR}"` when VAR contains `-e`, `-n`, `--`, `\n`, `\t` → May interpret as flags/escapes
    - `echo $VAR` (unquoted) → Word splitting and globbing issues
    - `echo "${VAR}" | command` → Unnecessary pipe (use here-string instead)
  - **SAFE ALTERNATIVES**:
    - `printf '%s\n' "${VAR}"` → Always safe, no flag interpretation, explicit format
    - `printf '%s' "${VAR}"` → Safe for output without newline
    - `echo "${VAR}"` → Safe ONLY if VAR is guaranteed to not contain echo flags (`-e`, `-n`, `--`)
    - For literal text: `printf '%s\n' "text"` or `echo "text"` (safe for literal strings)
  - **VALIDATION RULES**:
    - If VAR is user-controlled or file content → Use `printf` instead of `echo`
    - If VAR contains paths, URLs, or unknown content → Use `printf` instead of `echo`
    - If VAR is guaranteed safe (hardcoded, validated) → `echo "${VAR}"` is acceptable
    - Always quote variables: `echo "${VAR}"` not `echo $VAR`
  - **DETECTION**: Find all echo usage: `grep -nE '\becho\s' script.sh`, check for:
    - Echo with variables: `echo.*\$\{`
    - Echo with flags: `echo\s+-[en]`
    - Echo in pipes: `echo.*\|`
  - **AUTO-FIX**: Replace unsafe `echo` patterns with `printf '%s\n' "${VAR}"`
- D3c. **GREP UNSAFE PATTERNS**: Check for unsafe `grep` usage patterns:
  - **UNSAFE PATTERNS**:
    - `grep "${PATTERN}" file` when PATTERN contains regex special chars (`[`, `]`, `*`, `.`, `^`, `$`) → May match unintended patterns
    - `grep "${PATTERN}"` when PATTERN is user-controlled or file content → Command injection risk if pattern contains shell metacharacters
    - `grep -E "${PATTERN}"` with unvalidated pattern → Regex injection risk
    - `grep "${PATTERN}"` (unquoted pattern) → Word splitting and globbing issues
    - `grep pattern file` without error handling → May fail silently with `set -e`
  - **SAFE ALTERNATIVES**:
    - For literal strings: `grep -F "${PATTERN}" file` → Fixed-string matching (no regex interpretation)
    - For user-controlled patterns: Validate pattern before use, use `grep -F` when possible
    - Always quote pattern: `grep -F "${PATTERN}"` not `grep -F $PATTERN`
    - Add error fallback: `grep -F "${PATTERN}" file || echo ""` (with validation)
    - For regex: `grep -E "${PATTERN}" file` → Only use when pattern is trusted and regex is intended
  - **VALIDATION RULES**:
    - If pattern is literal string → Use `grep -F` (fixed-string matching)
    - If pattern is user-controlled → Use `grep -F` and validate pattern format first
    - If pattern is file content → Use `grep -F` or sanitize pattern before use
    - If pattern needs regex → Use `grep -E` but validate pattern is safe
    - Always quote patterns: `grep -F "${PATTERN}"`
    - Always handle errors: `grep -F "${PATTERN}" file || echo ""` (with result validation)
  - **DETECTION**: Find all grep usage: `grep -nE '\bgrep\s' script.sh`, check for:
    - Unquoted patterns: `grep\s+[^\"]+\s` (pattern not in quotes)
    - Missing `-F` flag: `grep\s+[^-F]` (when pattern should be literal)
    - Variables in patterns: `grep.*\$\{` (verify if `-F` should be used)
  - **AUTO-FIX**: Add `-F` flag for literal string patterns, quote unquoted patterns
- D3d. **ROBUST COMMAND SUBSTITUTION**: Check for unsafe command substitution patterns and ensure robust input/output handling:
  - **UNSAFE PATTERNS**:
    - `result=$(command "${VAR}")` when VAR contains shell metacharacters → Command injection risk
    - `result=$(command ${VAR})` (unquoted variable) → Word splitting and command injection
    - `result=$(command $@)` (unquoted `$@`) → Word splitting issues
    - `result=$(command)` without error handling → Masked failures (see H4)
    - `result=$(command || echo "")` without validation → Empty result may cause errors (see H4, F2)
    - `$(eval "command ${VAR}")` → NEVER use `eval` with variables (see K1)
    - `$(exec command)` → Replaces current shell, use only when intentional
